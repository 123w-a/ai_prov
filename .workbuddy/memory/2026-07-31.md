### 第八轮修复（AI 回答成品图裂图兜底）
1. **根因**: 后端 `agent.py` 的 `web_search` 工具用 Tavily 搜索图片，返回的图片来源是 Instagram（`lookaside.instagram.com`），后端再用荷兰代理 `images.weserv.nl/?url=` 包裹。实测两个 URL 在当前网络环境均 HTTP 000 不可访问，浏览器加载失败显示裂图。这是图片源网络不可达，非前端渲染问题。
2. **方案 A（用户选定的纯前端兜底）**: 在 `md_to_html` 的 `image_to_html` 里把 `<img>` 包进 `<span class="img-wrap">`，并加 `onerror` 处理器：图片加载失败时隐藏裂图、显示中文 fallback 提示「🍽️ 该成品图暂时无法显示 / 图片来源在当前网络下不可访问」。CSS 增加 `.img-wrap` 与 `.img-fallback` 样式。
3. **验证 onerror 不被剥离**: 查看 `streamlit.elements.markdown.clean_text` 源码确认 `unsafe_allow_html=True` 时只做 dedent+strip，不调 bleach，onerror 属性会完整保留到前端 dangerousSetInnerHTML。
4. **注意**: 方案 A 仅消除裂图、给出友好提示；图片本身仍因网络不可达而无法显示。若要真正显示图片需改后端（B 过滤被墙图源 / C 后端下载转 base64），用户本次选择只做前端兜底。
