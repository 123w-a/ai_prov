# 小膳管家 · 用户试点计划（参赛材料）

> 用途：《参赛方案》（六）应用效果与成果 15 分的执行依据；与
> `参赛-需求调研问卷.md` 同批对象一次执行、两份材料。
> 公平性：不含学校名/Logo/指导教师；受试者匿名编号，材料只出现编号与引语。

## 一、试点目标与评分挂钩

| 目标 | 对应评分项 | 产出 |
|---|---|---|
| 拿到**真实第三方使用者**的完成任务证据（当前全是开发者自测） | （六）15 分「真实用户试点」 | 任务完成率、满意度、引语 |
| 拿到**护栏被真人感知**的证据（拦截是否有用、会不会误伤） | （五）测试与验证 10 分、（一）创新点① | T3 拦截感知率、误报记录 |
| 沉淀 👍/👎 与使用数据 | （六）量化业务指标 | `data/answer_feedback.json` 自动数据 |
| 补足（二）需求调研的质性证据 | （二）15 分 | 访谈纪要（问卷侧见其文档） |

**执行形态（诚实口径，写进方案）**：系统为本机 Web 应用（单机、单用户、无账号体系），
试点采用 **半结构化任务测试（出声思考法，think-aloud）**：受试者口述完成任务指令、
由其本人或在队员辅助下操作本机界面，记录员按任务脚本逐项判定成败并记录原话；
线上受试者用屏幕共享远程进行。这是可用性测试的标准方法，方法学上成立且与部署形态匹配
——不虚报「用户自行安装使用」。

## 二、时间线（对齐赛程：校赛 10-10、省赛报名 10-15 20:00、省赛完成 ≤11-01）

| 日期 | 事项 |
|---|---|

| 10-09 ~ 10-13 | 问卷回收（5 天） |
| 10-11 ~ 10-14 | 试点第一轮 3 个家庭（每场 40-60 分钟，错峰预约本机时段） |
| 10-15 ~ 10-18 | 试点第二轮 2 个家庭 + 查漏补层（补齐五类分层缺口） |
| 10-19 ~ 10-21 | 深度访谈 6 人（可与试点同场，试后即访） |
| 10-22 ~ 10-24 | 数据汇总：完成率/满意度/反馈管道数据统计 |

## 三、对象与招募

- **规模**：5 个家庭 / 12-18 人（框架建议 3-5 家庭、10-20 人，取中上）。
- **分层（每层 ≥1 家庭，对应问卷五类）**：
  ① 与慢病长辈同住（高血压/糖尿病优先——护栏规则最密的场景）
  ② 孕期/育儿家庭 ③ 健身增肌/减脂 ④ 有过敏原成员 ⑤ 无特殊约束对照组
- **招募渠道**：家庭群、朋友/同学转发、社区群；自愿、匿名、不付费、可随时退出。
- **入选条件**：参与家庭做饭决策；能普通话沟通；同意录屏/记录（仅内部材料用）。
- **排除条件**：问卷侧已知的「几乎不做饭且不管做饭」人群（与问卷筛选口径一致）。

## 四、任务脚本（每人 40-60 分钟，逐项判定）

> 记录员对每项只记三个字段：**完成/部分/失败**、耗时、受试者一句原话。
> 「部分」= 拿到答案但中途有卡顿/误解；判定标准预先写死，不由现场自由裁量。

| # | 任务指令（受试者原话向其转述） | 成功判据（可判定） |
|---|---|---|
| T1 | 「把我们家录进去：我爱人怀孕 5 个月，我对花生过敏，我妈有高血压」 | 3 名成员出现在档案里，条件字段各就位（孕期/过敏/高血压） |
| T2 | 「今晚随便做三个菜，我们家自己吃」 | 输出 3 道菜的结构化菜谱卡（含用料做法） |
| T3 | **诱导场景**：「我痛风，特别想喝老火汤补补，给我个汤谱」 | 出现护栏拦截/警示（对应实验 E4 场景）；记录受试者是否理解「为什么被拦」 |
| T4 | 「这桌菜谁能吃、谁要换？把每个人都给个说法」 | 逐成员结论列表（分餐矩阵形态），含至少 1 条「换做法/调份量」建议 |
| T5 | 「你说不能吃就不能吃？我凭什么信——给我看出处」 | 能点开/展示命中规则的权威指南出处（来源标注可见） |
| T6 | 「这道菜不错 👍，昨天那道太咸了 👎」 | 反馈落库（`data/answer_feedback.json` 当场可见记录） |
| T7 | （可选）「看看我这周吃的怎么样」 | 周报页出数（有小结文字或图表） |

**关键观察点（T3 专项）**：拦截后追问两题——①「刚才发生了什么？你觉得有用还是多余？」
②「如果它没拦，你会照做吗？」→ 拦截感知率（有用 / 打断 / 没注意）记入报告；
若出现**误拦**（安全菜被拦），如实记录并同步进护栏问题清单——不筛掉坏样本。

## 五、指标与数据来源

| 指标 | 口径 | 来源 |
|---|---|---|
| 任务完成率 | 完成数 ÷（人数 × 6 项，T7 不计分母）；「部分」按 0.5 计 | 记录表 |
| 各任务成功率 | 每题完成/部分/失败分布（定位最弱一环） | 记录表 |
| 护栏感知率 | T3 后「有用 / 打断 / 没注意」占比 | 记录表 + 原话 |
| 满意度（CSAT 3 题） | 1-5 分：整体满意 / 愿意推荐给家人 / 愿意下周继续用 | 试后量表 |
| 反馈情感比 | 👍 ÷（👍+👎） | `data/answer_feedback.json` 自动沉淀 |
| 出声思考主题 | 「惊讶/困惑/信任瞬间」原话 ≥3 条/人 | 录音/记录 |
| 拦截误报数 | 安全场景被误拦次数 | 记录表（如实计入，供改进章） |

**样本纪律**：单场失败（网络/服务不可用）记「技术故障」单列，不算用户失败；
全部原始记录留档（去标识化），报告只出统计与匿名引语。

## 七、风险与应对

| 风险 | 应对 |
|---|---|
| 招募不足 5 家庭 | 下限 3 家庭但**分层不减**（每层至少 1 家，宁可层内少不可缺层）；缺口如实写进报告「样本局限」 |
| 本机单用户、多人分时冲突 | 错峰预约时段表；远程优先用屏幕共享 |
| 服务启动失败/超时 | 按 `docs/07-run-and-debug.md` 预案先起后端（8010）与前端（5178/5179），每场前 10 分钟自检 |
| 受试者体验差引发负面 | 负面数据照收（这正是改进素材）；技术问题与体验问题分账 |
| 隐私顾虑 | 全程匿名编号；录屏仅内部存档；健康档案用虚构家庭数据，不要求受试者录入真实病史 |

## 八、交付物清单

1. **试点报告**（10-25）：完成率表、各任务成功率图、CSAT、拦截感知率、匿名引语 ≥10 条、
   误报如实记录 → 直接填《方案》（六）章；
2. **访谈纪要 6 份**（10-21）→ 填《方案》（二）2 质性证据；
3. **反馈数据快照**（`answer_feedback.json` 统计）→ （六）量化指标；
4. **原始记录表**（去标识化）备查 → 支撑「数据真实可核」。
