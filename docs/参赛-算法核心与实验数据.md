## 一、三个算法核心与公式

### A. 双通道混合检索 + 交叉编码重排（知识可溯源）

**问题**：用户问「痛风能不能喝老火汤」，口语化、常带错字，单一向量检索召回不稳；
答案必须落到权威指南原文（可溯源是护栏可信的前提）。

**① 查询改写**（`rag/query_transform.py`）：口语/绕/错字先改写成规范查询，
再以**多查询**发起检索，跨查询结果做第二次 RRF 合并：

```
多查询融合：  score(q→d) = Σ_j 1 / (k + rank_j(d))          （retriever.py L313-324）
```

**② 双通道 RRF 融合**：稠密向量（bge-small-zh-v1.5）与 BM25 关键词各出一份
有序列表，按倒数排名融合（k=60，`retriever.py` L213/L280-287）：

```
RRF(d) = 1/(k + rank_dense(d)) + 1/(k + rank_bm25(d)),   k = 60
```

**③ 交叉编码重排**：融合候选（默认取 10 个）交 `bge-reranker-v2-m3` 打
query-document 对分数，按分重排后截断（`retriever.py` L292-300）：

```
最终序 = argsort_{d∈C} score_CE(q, d),   C = top-10(RRF 融合)
```

**④ 索引侧 Contextual 切片**（`rag/ingest.py` L27）：每个切片前拼「它在原文档中的
位置与上下文」物语后再向量化，降低裸切片的语义孤岛。

**公平性标注**（规则（三）要求）：RRF 出自 Cormack et al., SIGIR 2009；BM25 出自
Robertson & Zaragoza, FnTIR 2009；bge 系列为 BAAI 开源模型；Chroma / LangGraph 为
开源组件。本项目贡献在于**面向膳食指南问答的链路组合与评测闭环**，非上述算法原创。

### B. 「生成 → 审计 → 重生成」确定性硬护栏（输出不自证）

**问题**：大模型会顺着用户的错误前提走（「我爸痛风想喝老火汤补补」），且自己
不知道自己错了——靠 prompt 约束是概率性的，餐桌上错一次就是健康事故。

**① 语境化违禁判定**（`domain/nutrition_rules.py` L118-146）：不是关键词 grep。
命中判定 = 关键词出现 ∧ 该次出现不落在任何否定/限定语境：

```
V_kw(x, c) = { kw ∈ F(c) : ¬Q_prefix(x, kw) ∧ ¬Q_bridge(x, kw) ∧ ¬Q_post(x, kw) }
```

- `Q_prefix`：关键词紧邻前缀是限定词（不吃/不放/避免/拒绝…，含否定反转修正）；
- `Q_bridge`：限定词与关键词之间只隔一个动词（「拒绝**饮**酒」），否定语义不被
  单字打断（2026-10-08 对照实验发现并补上）；
- `Q_post`：关键词后 4 字符是后置否定（「酒**都不喝**」）。

**② 数值阈值审计**：钠、添加糖从文本**抽真实克数**再比上限，不是词频计数：

```
Na(x) = Σ salt_total_g(文本中的「盐/酱油/… 克数」)，  超 cap(c)=5g 即违禁
Sugar(x) = Σ sugar_total_g(白砂糖/冰糖/…)，          超 scap(肥胖)=25g 即违禁
违规集 V(x, C) = V_kw(x,·) ∪ {Na > cap} ∪ {Sugar > scap}
```

**③ 闭环重生成**（`agent/graph.py` L2559-2666）：审计不过 → `describe(V)` 生成
带出处的中文反馈 → 模型重写 → 再审；**结局三档、绝不静默放行**：

```
x_{t+1} = G(prompt, describe(V(x_t, C))),   t < MAX_VERIFY
终态 ∈ { 合规出菜 : V(x_t)=∅
       | 附警示放行 : t=MAX_VERIFY ∧ V≠∅ → verify_status=degraded，
         正文附「⚠️ XX忌XX」警示（graph.py L2661 注释：绝不静默放行）
       | 过敏原直拒 : 过敏原违禁达上限 → verify_status=blocked，不出菜（L2629） }
```

曾命中但重生成至合规的记入 `verify_violated` 留痕，可审计「拦过什么」。

**七病种规则全带官方出处**（成人高血压/糖尿病/高脂血症/痛风/慢性肾脏病/肥胖食养
指南 2023-2024 版、中国孕期妇女膳食指南 2022），每条命中返回 `source` 字段可溯源。

### C. 多成员家庭约束下的分餐矩阵（场景独有）

**问题**：一桌菜要同时满足「孕期控钠控生冷 + 增肌补蛋白 + 共同过敏原排除」——
现有下厨房/热量 App 都是**单人口径**，没有「一桌菜对每个成员分别裁决」的形态。

**① 约束条目归一**（`domain/constraint_rules.py` L7-10）：采集端与审计端共用
条目结构 `(member, dimension, value, severity, scope)`，四维：

```
dimension ∈ {allergen 安全, chronic 慢病, texture 口感, energy 能量}
severity  ∈ {hard 硬约束, soft 偏好}      scope ∈ {always 长期, once 本次}
```

**② 分餐矩阵**（`build_matrix`, L329）：菜 × 成员逐格裁决，硬约束优先级高于偏好：

```
M[m][d] = verdict( F(member_m), dish_d ),   verdict ∈ {通过, 换菜, 调做法, 调份量, 待确认}
```

**③ 成员调整外推**（`build_member_adjustments`, L413）：矩阵 → 逐人可执行建议
（「妈妈这份少放盐、爸爸这份加个蛋」）。过敏原维度走 `allergen_rules.py` 同结构
审计（hard 违禁 / notice 提示两级），与慢病规则分引擎、互不降级。

### E4 LLM 首稿裸输出 vs 护栏闭环（`experiments/ab_llm_guardrail_e2e.py`，端到端）

设计：7 病种 × 2 问法（直接问 / 带错误前提诱导，如「痛风想喝老火汤补补」）共 14 案例，
本地 mimo（`xiaomi/mimo-v2.6-flash`，经本机 commandcode-proxy）生成首稿 → 统计含 ≥1 条
硬禁忌的首稿占比（= 裸输出用户可见违禁率）→ 走生产同款「describe 反馈 → 重生成（≤3 轮）」
→ 统计最终稿残留。conditions 按 prompt 声明病种硬编码（等价于档案激活护栏的口径）。

**三轮演进（2026-10-08 → 10-09）：发现问题 → 修复 → 复测的完整闭环**

| 轮次 | 反馈/判定状态 | 闭环成功例 | 首稿裸违禁（分母=成功例†） | 3 轮后残留 | call_failed |
|---|---|---|---|---|---|
| R1 基线 | 关键词级反馈 | 10/14 | 12/14 = 86%（首稿 14 例全取得††） | **1/10**（高血压：钠账压不下） | 4 |
| R2 +数值账单 | describe 附逐项克数+差额 | 11/14 | 9/11 = 82% | **4/11**（暴露判定层误报） | 3 |
| R3 +语境第二轮 | 并列组桥/否定词补表/数值让路 | 10/14 | 8/10 = 80% | **0/10 = 0%** | 4 |

† R2/R3 脚本按闭环成功例计首稿（call_failed 例的首稿另有数字但不进分母）；†† R1 首稿全取得故分母 14。
首稿裸违禁率三轮均在 80-86% 区间——它是模型裸输出属性，与护栏改动无关，轮间波动属正常采样噪声。
call_failed 全部为 mimo 网关返回 content=null（实验脚本重试后仍失败），如实记录、不计入闭环分母。

**R2 残留 4 例的根因不是模型顽固，是判定层误报**（这正是改进闭环的起点）：
① 「盐」词级命中与数值账单**双路径不对称**——模型已把钠降到合规、词级仍拦，3 轮无解白耗到 degraded；
② 「避免生冷**和**生食」「不喝浓茶**和**咖啡」并列组里限定词被连词隔断，紧邻匹配漏豁免；
③ 「反式脂肪控制在 2 克以内」这类**合规限制表述**被词级误拦（lipid 例残留实锤）；
④ 模型改口「少吃生鱼」等弱化表述时按保守立场仍提示（预期行为，非误报）。

**R3 三项修复**（回归测试 34 → 47 例）：并列组桥（限定词后可隔「组内词+连词」序列，组内词
必须来自本规则词表，可判定不泛化）+ 否定词补表（不碰/不食/勿食/禁食）+ 数值让路
（salt 模式用量带数字 → 交数值层账单管辖；forbidden 模式「限制语 + 数字」双条件才豁免，
缺一照拦——防「一天吃 4 克」这类摄入描述被误放）。

**R1 的历史观察（催生数值账单）**：高血压例 3 轮重生成违禁 3→2 未清零——模型在「少盐」
反馈下改用味精/鸡精/蚝油等钠源替代。两处根因：反馈只给结论不给账单（模型不知道减哪几项），
且旧 `_salt_total_g` 硬编码窄词表根本算不到鸡精/味精。R2 起 describe 附逐项账单
（生抽 3g + 盐 2g = 超 Xg，并明示「仅替换品类无效」），钠源表改为复用 `_SALT_SEASONING`。

复跑：`.venv\Scripts\python.exe experiments\ab_llm_guardrail_e2e.py`（需 .env 配 mimo 三键，
约 10-20 分钟；结果 CSV 按轮留档 `*.pre-bill.csv` / `*.round2.csv`，当前轮覆盖主 CSV）。

**空返回（content=null）链路查证（可靠性层素材，2026-10-09）**：
- 事实一：主生成节点 `chef_agent_node` 的 3 次重试**只捕获异常**（5xx/连接失败/限流），
  HTTP 200 + `content=null` 不算异常、**不触发该重试**（`agent/graph.py` L1655-1666 代码证据）。
- 事实二：下游 `structure_answer` 的结构化链自带「解析失败回灌修正、重试耗尽才降级」
  （L2346），空文本可走该自愈路径；E4 的首稿 null 已由 `max_tokens=2000` + 脚本外层
  重试消除（首稿 14/14 取得）。
- **未验证边界（不冒充已测）**：「主节点收到 null 后全链路落点」未做故障注入实测；
  生产侧亦未收到空屏复现报告——无正反两方面证据。
- 处置决定：依《AGENTS》冻结条款，无可复现生产问题**不改**主节点重试与输出兜底；
  若生产复现空屏，按「先说明复现证据与修改范围、再获用户同意」的流程处理。
  实验中的 call_failed（每轮 3-4/14，网关侧不稳定）如实计入材料可靠性说明。

## 三、创新点表述（对「创新性 14-20 档」的论证）

官方三档：14-20 = 「全新的 AI+行业场景**融合应用模式**、具有开创性」；
0-6 = 「仅做常规应用」。据此，创新点不写「用了大模型/RAG」（那是常规应用），
而写**下面三条融合模式**——每条都以本文实验数字为证：

1. **「模型生成、规则兜底」的双层确定性融合**：大模型负责自然表达，确定性规则
   引擎在输出前强制审计并驱动重生成，违规集每条带国家指南出处——模型不自证、
   不可信的环节由可复跑的规则接住。证据：E2（关 0/开 10 拦截）、E4（首稿裸违禁
   稳定在 80-86%，经三轮「发现→修复→复测」演进闭环残留 1 → 4 → **0**）、
   E3（语境判定零误报且检出无损）。三轮演进本身即（五）测试与验证的
   「发现问题-修复-回归」闭环实例，非一次性演示。
2. **权威指南的可溯源问答链路**：混合检索+重排+Contextual 切片服务 27 份官方
   PDF，回答引用必带出处，为护栏提供「查得到的依据」。证据：E1（recall@3=1.0）。
3. **多成员家庭的逐人裁决形态（场景独有）**：一桌菜 × 每人四维约束 → 分餐矩阵
   → 逐人调整建议；同类产品（下厨房/薄荷健康等）均为单人口径，**此形态市场无
   对应物**，是「场景开创性」的主论据。证据：E2 的 B 组（多规则并存不互相降级）
   与 domain 层 47 例测试。

**同类对比口径**（答辩可能被问）：与通用 AI 菜谱应用的差异 = ①单人口径 vs 逐人
裁决；②概率性 prompt 约束 vs 确定性规则闭环；③无据生成 vs 出处可溯。不贬低同行，
只陈述形态差异。
