## 2. 逐节骨架

### （一）项目概述 【创新性 20 分】

**1. 背景与意义**　【需写】+【缺统计数字与出处】

- 官方要求：行业/学科背景 → 问题现状 → 对民生改善的影响 → 「AI+场景创新」解决它的意义。
- 要写三段：
  1. **行业背景**：特殊人群（孕期、老年、慢病）与家庭多成员共餐的营养管理现状；国家《国民营养计划》与膳食指南的政策要求。素材：`kb/0_总纲/`、`kb/1_慢病食养指南/`、`kb/4_特殊人群膳食指南/`（27 份权威资料可引）。
  2. **问题现状**：菜谱 App 只搬运、通用大模型不安全、家庭约束分散——三类痛点各给一个具体场景。
  3. **意义**：把膳食指南从政策倡导变成可实时调用的决策护栏。
- **【缺】**权威统计数字（慢病人群规模、特殊人群营养管理缺口等）→ 必须查证并列出参考文献，**不许估**。
- **【已有】**真实场景故事：两位成员（孕期 + 增肌，共同忌口芹菜）+ 冰箱实测食材（鸡蛋/西兰花/面条/大蒜）——脱敏后作为「场景挖掘」实证写入，这是本作品最有力的差异化叙事。

**2. 目标定位**　【需写】

- 官方要求：解决什么具体问题、达成什么技术指标、产生什么效益、在「AI+场景创新」中的定位。
- 要写：
  1. 一句话定位：**家庭膳食决策智能体**（与简介定稿完全一致）。
  2. **量化技术指标**（第五、六章要逐条回收）：护栏审计 p50 ≤1ms；检索 recall@3 ≥0.75（实测 39/39）；三轮闭环残留违禁 0/10；三端自动化测试全绿。
  3. 核心定位：不做菜谱内容平台，做**餐桌决策护栏**。
- 红线：指标只能取第五、六章能兑现的，不许写交接指标。

### （二）需求分析 【15 分】—— 当前最大短板

**1. 问题剖析**　【需写】

- 官方要求：从**场景应用**和**人工智能技术**两个维度剖析问题本质、关键难点、现有方案不足。
- 要写：
  1. 场景维度三类痛点：① 通用菜谱不认人（同一道菜对孕期/高血压/健身者风险不同）；② 健康约束分散（画像、忌口、剩菜库存、上周吃过的无法一起决策）；③ 老年照护与外卖决策缺少可核对的红线。
  2. 技术维度关键难点：① 大模型会顺着错误前提给出与慢病冲突的建议；② 长尾规则（过敏原、嘌呤、汞含量）靠提示词守不住，必须确定性判定；③ 权威依据需可溯源到原文。
  3. **现有方案对比表**（官方要求突出差异化）：传统菜谱 App ／ 通用大模型问答 ／ 人工营养师 ／ 本作品，按「是否认人、是否带权威依据、是否可即时、成本」四列对比。
- 红线：本作品「附近餐厅/在外点单」为演示数据，对比表里不得把它列为已实现能力。

**2. 用户需求调研**　【缺 · 10-13 回收】

- 官方要求：问卷、访谈、案例等方式收集目标用户需求，归纳功能/性能/操作期望。
- 工具已成稿待执行：`docs/参赛-需求调研问卷.md`（问卷 22 题 + 访谈提纲 10 题 + 统计分析计划 7 图 1 表）。
- 回收后本节要填：样本量、统计图表（按计划出图）、访谈纪要引语、需求归纳结论。
- 说明用户画像差异：官方举例是「科研人员、行业从业者」，本作品面向**家庭用户**，需一句说明为何选择 C 端家庭场景（场景创新性就在「一家多口、需求冲突」）。
- 红线：问卷回收前，本节只能写方法与计划，**不得写任何比例数字**。

### （三）解决方案设计 【20 分】—— 全文最强章

**1. 技术路线规划**　【已有主体，需成文】

- 官方要求：整体技术路线；算法/模型选型；与场景的融合路径与核心逻辑。
- 核心叙事（一句话）：**大模型负责生成、RAG 负责有据可查、确定性规则负责兜底拦命**。
- 三个算法核心（公式与 file:line 见 `docs/参赛-算法核心与实验数据.md`）：
  1. 混合检索：BM25 + 向量双通道 → RRF(k=60) 融合 → 交叉编码器重排；查询改写 + Contextual Retrieval。
  2. 确定性护栏闭环：规则生成 → 审计 → 带出处反馈重生成；终态三档（合规出菜／degraded 附警示放行／过敏原违禁 blocked）。
  3. 多成员约束分餐：约束元组 (member, dimension, value, severity, scope) → 菜品×成员矩阵判定（一桌菜按每位成员分别裁决）。
- 必须说明**为什么不用纯提示词**：长尾规则在生成式路径上不可靠（用第五、六章的对照实验数字支撑）。

**2. 系统架构设计**　【已有·图】

- 官方要求：绘制系统架构图，含数据层／算法层／应用层，说明各层功能与数据交互，具备可扩展性与稳定性。
- 已有：`docs/参赛-架构图.html`（可交互 SVG，9/9 校验通过，带 PNG 导出）；文字版 `docs/01-architecture.md`。
- 要写：把架构图的三层与官方要求逐层对齐；说明数据交互流程（SSE 流式对话 → 编排 → 护栏 → 结构化菜谱卡）；诚实标注当前为**单机单用户演示态**，可扩展性写改进方向。

**3. 功能模块设计**　【已有·表】

- 官方要求：核心功能模块的功能、实现方式与协同关系。
- 已有模块表（含代码与测试支撑，见框架文档 §（三）3）：家庭画像 / AI 对话配餐 / 健康护栏 / 知识库 RAG / 周报 / 反馈闭环 / 冰箱识别 / 语音输入 / 收藏与偏好。
- 每个模块写三行：功能 → 实现（文件定位）→ 与其他模块的协同。
- 红线：语音未配置时不可用、附近餐厅为演示数据，必须在模块旁标注。
