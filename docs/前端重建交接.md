> **诚实声明**：我**没有**调用 `POST /api/chat`。理由：它会真实产生大模型 / Tavily 搜索 / 通义万相生图 / OSS 四类账单，并写入 `sessions/` 里用户的真实历史。按数据卫生纪律，我不在交付验证里做不可逆的付费写入。
> 所以下面这段的证据等级是**【文档】+【源码】**，**不是【实测】**。你接手后要自己验证（§5.4 给了安全的验证方式）。

- 请求是 **`multipart/form-data`，不是 JSON**；`want_image` 是**字符串 `"1"`/`"0"`，不是布尔**。
- 事件以 `\n\n` 分隔，每条 `data: {json}`。
- **必须按有序 else-if 匹配**（有前缀包含关系，乱序会误判）：
  1. `{"working":true}` / `{"status":"working"}`
  2. `{"heartbeat":{"elapsed":12}}`
  3. `{"image":{record_id,turn_id,index,url,ai_generated}}`
  4. `{"image_failed":{record_id,turn_id,indexes}}`
  5. `{"token":"…"}`
  6. `{"structuring":true}`
  7. `{"answer":{ChefAnswer}}`
  8. `{"stage":"thinking"}`
  9. `{"finish":true,session_id,record_id}`
  10. `{"error":"…"}`
- `stage` 取值：`thinking` / `writing` / `searching` / `auditing` / `generating_image` / `structuring` / `switching_model`。
- **两个必须照抄的怪癖**：
  1. **token 过滤**：把 token `trim()` 后，若以 `{` 开头 `}` 结尾、或以 `[` 开头 `]` 结尾，**丢弃**（服务端会把 JSON 片段混进 token 流）。
  2. **配图事件在 `answer` 之后异步到达**（可能几十秒后），靠 `turn_id` 可取消（→ #47）。
- 解析方式：现有实现用手动 `resp.body.getReader()` + `TextDecoder`，按 `\n\n` 切块、剥 `data:` 前缀、`JSON.parse`（失败 `continue`）。**没有用 `EventSource`**（因为要 POST + 自定义 body）。

> 【分析】**不一致点**：`frontend/web/README.md` 只列了 7 个事件（`working/heartbeat/token/structuring/answer/finish/error`），**漏了 `image`、`image_failed`、`stage`**。以 §1.9 的 10 个为准（这个来自 API 文档 + `client.ts` 的 `ChatHandlers` 接口）。
