## 1. 现状取证

### 1.1 布局结构

`next/views/WeeklyView.tsx` 的 `.wk-cols` 下是三个 `.wk-col`，各自独立堆叠：

| 列 | 卡片 | 相对高度 |

### 1.2 红点为什么"看不见"

`next/blocks/WeekStatCards.tsx::WeekLights` 实证：

- 每个点渲染为 `<i className="wk-pip" data-c={p.c} key={p.key} />` —— **空标签，无 `title`、无 `onClick`**；
- 外层 `<span className="wk-pips" aria-hidden="true">` —— 整块对屏幕阅读器隐藏，169 条信息在无障碍层面完全丢失；
- `panels.css` 里 `.wk-pips { display:flex; flex-wrap:wrap; gap:9px }`，`.wk-pip` 是 13px 圆点 —— **纯平铺，没有日期分组，看不出时间顺序**；
- 口径：一餐一点，取该餐最差那盏灯（有红取红 > 有黄取黄 > 全绿取绿）。这是展示口径，达标判据仍然只有后端 `is_meal_on_target` 一处。

图例已经带文字「绿 45 黄 112 红 3」，这点是做对的（不单靠颜色传态），不要动。

## 2. 档①：只修红点（★☆☆ 难度，1 个文件）

### 2.1 给每个点加 tooltip

**文件**：`next/blocks/WeekStatCards.tsx` → `WeekLights`

先给 pips 元素带上文字信息：

```tsx
// 现在
pips.push({ c, key: m.ts + m.dish })

// 改成
const off = m.lights
  .filter((l) => l.level !== 'green')
  .map((l) => `${l.nutrient}${l.level === 'red' ? '超标' : '偏高'}`)
  .join('、')
pips.push({ c, key: m.ts + m.dish, tip: `${mealStamp(m.ts)} ${m.dish}${off ? ' · ' + off : ''}` })
```

渲染处：

```tsx
{/* 现在 */}
<i className="wk-pip" data-c={p.c} key={p.key} />

{/* 改成 */}
<i className="wk-pip" data-c={p.c} key={p.key} title={p.tip} />
```

`mealStamp` 来自 `next/data/weekFacts.ts`，已在成员详情抽屉使用。**blocks 层 import data 层符合分层契约**（weekFacts.ts 的文件头注释明确说明它是为 blocks 与 views 共用而抽到 data 层的）。

效果：鼠标停在任一点上，就能看到「10-13 22:06 宫保鸡丁（无花生版） · 钠超标、糖偏高、脂肪偏高」。红点不再需要靠颜色猜。

### 2.2 按 7 天分组（性价比最高的一步）

现在 169 个点是一整块，红点埋在里面没有位置感。按天切成 7 行后，红点立刻落到「10-13」和「10-15」两行。

```tsx
// 分组（保持时间顺序，不排序字符串）
const groups: Array<{ day: string; items: typeof pips }> = []
for (const p of pips) {
  const day = p.key.slice(0, 10)
  const last = groups[groups.length - 1]
  if (last && last.day === day) last.items.push(p)
  else groups.push({ day, items: [p] })
}
```

渲染：

```tsx
<div className="wk-pips" role="img" aria-label={`本周 ${rated} 餐，绿 ${green} 黄 ${yellow} 红 ${red}`}>
  {groups.map((g) => (
    <div className="wk-pip-row" key={g.day}>
      <span className="wk-pip-day">{mealStamp(g.day + 'T00:00').slice(0, 5)}</span>
      <span className="wk-pips-inner">
        {g.items.map((p) => (
          <i className="wk-pip" data-c={p.c} key={p.key} title={p.tip} />
        ))}
      </span>
    </div>
  ))}
</div>
```

`weekly.css` 追加（**不要写进 panels.css**，panels.css 是共用的基础层，weekly.css 是覆盖层，它排在 panels.css 之后）：

```css
.wk-pip-row { display: flex; align-items: flex-start; gap: 8px; margin-bottom: 5px; }
.wk-pip-day { flex: 0 0 34px; font-size: 11px; color: var(--ink-soft); line-height: 13px; }
.wk-pips-inner { display: flex; flex-wrap: wrap; gap: 6px; }
```

注意：`.wk-pips` 现在是 `flex-wrap: wrap; gap:9px`，改成按行容器后，行内 gap 用 6px 才不至于一天排不下 48 个点（10-13 有 48 条记录）。**这一点要实测 10-13 行的换行情况**。

### 2.3 无障碍

不要只删 `aria-hidden` 就完事 —— 那会让屏幕阅读器逐个朗读 169 个空标签。正确做法是**外层给汇总语义、内层保持装饰**：

- 外层 `.wk-pips` 加 `role="img"` + `aria-label="本周 169 餐，绿 45 黄 112 红 3"`
- 内层 `<i>` 保持无文本（不需要 `aria-hidden`，`<i>` 本身没有可读内容）

### 2.4 回归点

改完必须看这几种情况，不要只看有数据的那一版：

| 场景 | 期望 |
|---|---|
| 本周只有 1 餐 | 点阵 1 行 1 点，不塌陷 |
| 本周全部绿（无红无黄） | 图例只剩「绿 N」，不出现「黄 0 红 0」 |
| 某天 48 条（10-13） | 该行正常换行，不撑破卡片宽度 |
| 全部 9 条都没灯（`pips.length === 0`） | 组件返回 `null`，页面不出现空卡 |
| 档位是未知值（非 red/yellow/green） | `mealLevel` 回落到 `g` 画点，但文字仍是原值 |

## 3. 档②：填空白（★★☆ 难度，新增 1 组件 + 改 1 组件）

### 3.1 「红点 N 餐」清单卡 —— 推荐优先做

**为什么是它**：它是唯一同时满足「填空白」和「解决红点不可追溯」的方案，而且数据已经在前端手里（`view.mealsDetail` 已含 `ts` / `dish` / `lights`），**不需要改后端**。

**放哪里**：列 3，卡6 可执行建议的下面（列3 空约 172px，正好一张卡的高度）。

**新建** `next/blocks/WeekRedMealsCard.tsx`：

```tsx
/**
 * 卡 7「红点 N 餐」：把卡 2 点阵里看不出来的红点摊开成清单。
 * 数据来自已有的 mealsDetail，不新增接口、不新增算法——
 * 判红的口径与 WeekLights 完全一致（取该餐最差灯），避免两处判定分叉。
 */
import { CardHead } from './WeekCardShell'
import { mealStamp } from '../data/weekFacts.ts'

type MealRow = { ts: string; dish: string; onTarget: boolean; lights: Array<{ nutrient: string; level: string }> }

export function WeekRedMealsCard({ mealsDetail, onPick }: { mealsDetail: MealRow[]; onPick: (dish: string) => void }) {
  const reds = mealsDetail.filter((m) => m.lights.some((l) => l.level === 'red'))
  if (reds.length === 0) return null   // 全绿时不占位，不留空卡
  return (
    <section className="wk-card is-red">
      <CardHead n="7" title={`红点 ${reds.length} 餐`} note="（这几餐有指标超标）" />
      <ul className="wk-reds">
        {reds.map((m) => {
          const bad = m.lights.filter((l) => l.level === 'red').map((l) => l.nutrient)
          return (
            <li key={m.ts + m.dish}>
              <span className="wk-reds-t">{mealStamp(m.ts)}</span>
              <span className="wk-reds-d">{m.dish}</span>
              <span className="wk-reds-r">{bad.join('、')}超标</span>
              <button type="button" onClick={() => onPick(m.dish)}>再做一版</button>
            </li>
          )
        })}
      </ul>
      {reds.every((m) => m.lights.some((l) => l.nutrient === '钠' && l.level === 'red')) ? (
        <p className="wk-card-foot">这几餐超标项全是钠，可以优先把盐和酱油再压一点。</p>
      ) : null}
    </section>
  )
}
```

**注意**：`onPick` 已在 `WeeklyView.tsx` 内定义（派发 `dish-pick` 事件并切到 `room=tonight`），直接传下去即可，别重新写一套跳转。

**挂在** `WeeklyView.tsx` 列 3：

```tsx
<div className="wk-col">
  <WeekRateCard ... />
  <WeekAdviceCard ... />
  <WeekRedMealsCard mealsDetail={view.mealsDetail} onPick={pick} />
</div>
```

### 3.2 反馈空态改成真入口

**现在**：`WeekTipCards.tsx::WeekGuardCard` 里 `feedback.count === 0` 时显示「还没有收到反馈」+ 插画，占了列1 约 52px 且毫无作用。

**能做成真按钮**：后端已有 `POST /reports/feedback`，入参 `{dish, rating(1-5), tags?, comment?}`，`dish` 必填、`rating` 必须是 1–5 整数 —— 所以**可以做成真打分，不是假交互**。

改法：

```tsx
{feedback && feedback.count > 0 ? (
  /* 原有：本周反馈 N 条 + 标签统计，不动 */
) : (
  <div className="wk-card-fb is-empty">
    <p className="wk-card-fb-k">这周的菜，哪道最合口？</p>
    <ul className="wk-fb-quick">
      {quickDishes.slice(0, 3).map((d) => (
        <li key={d}>
          <span>{d}</span>
          <button onClick={() => sendFeedback(d, 5)}>不错</button>
          <button onClick={() => sendFeedback(d, 2)}>一般</button>
        </li>
      ))}
    </ul>
    <p className="wk-card-foot">点一下就算反馈，会算进下周的推荐。</p>
  </div>
)}
```

`quickDishes` 取 `view.dishes` 前 3 个（已在 `WeeklyView` 里）；`sendFeedback` 就是 `fetch('/api/reports/feedback', {method:'POST', body: JSON.stringify({dish, rating})})`。

**风险点**：打分后该卡要能立刻刷新，否则用户点完没反应。最小做法是本地置一个 `submitted` state 把按钮换成「已记下」，不重新拉整页周报。

### 3.3 布局分配结论

| 位置 | 填什么 | 解决 |
|---|---|---|
| 列 1 底部（约 134px） | 反馈空态改引导（3.2） | 空态变入口，高度自然长起来 |
| 列 2 | **不加**，它是基准列 | — |
| 列 3 底部（约 172px） | 红点清单卡（3.1） | 填空 + 红点可追溯 |

两处填完，三列高度大致齐平。**仍然不要把 `.wk-cols` 改成 grid**。

## 4. 档③：数据修复（★★☆ 难度，会写数据文件，需单独授权）

### 4.1 成员归属回填（做成员卡的唯一前置）

**现状**：本周 169 条里 **163 条没有 `member`/`members`**，仅 6 条有。

`scripts/backfill_meal_members.py` 已存在（2,664 B），按「session + dish 唯一匹配」回填。**跑之前先备份 `data/meals.json`**，跑完对比回填条数与未匹配条数。

> 上一版方案里我建议过「加成员达标率条」，现按实测撤回：分母不对时做出来的成员达标率是假数据。**先回填，再谈这张卡。**

### 4.2 清理脏值

回填后要单独查一遍 `member` / `members` 里的非人名取值。当前实测有一个 `'速度'`（出现在 `members` 里）。这类值会变成成员卡片上的一个"成员"，必须清掉或修正。

### 4.3 `dish_assets.json` 查表键归一

**根因**：表里键是**基础菜名**（`番茄炒蛋`、`宫保鸡丁`），而 `meals.json` 记的是**带后缀全名**（`番茄炒蛋（少盐版）`、`宫保鸡丁（无花生·家庭减钠版）`），带括号后缀的一律查不到。

最小改法：查表前先归一 —— 去掉全角/半角括号及其内部内容再查，仍查不到才回落到占位图。

```
"番茄炒蛋（少盐版）"       → "番茄炒蛋"        → 命中
"宫保鸡丁（无花生·家庭减钠版）" → "宫保鸡丁"    → 命中
```

**注意**：归一只能用于**取图**，不能用于写回。写资产时仍用全名做键，否则两版菜谱会互相覆盖。

### 4.4 Top5 缺图补齐

实测本周 Top5 的图片状态：

## 5. 顺带建议修的两个口径问题

### 5.1 「169 餐」其实是 169 道菜

`reports_route.py::record_meal` 是**每产出一道菜就写一条**，记录里没有「这顿饭是否真的做了、是否真的吃了」字段。所以：

- 169 条 ≠ 169 顿；
- 人均 42.3 餐/周 = 一天 6 顿，不可能；
- 卡2 的标题写「营养达标情况（按餐次）」，与数据不符。

**只需改文案**：把「按餐次」改成「按菜品」，或把「本周餐次」改成「本周菜品记录」。若要做真正的"餐次"，得按 `session + 同一天` 聚合，那是另一件事。

> 数据本身建议不动（用户已明确要求不改测试数据），这里只是不要把"菜品条数"说成"餐次"。

### 5.2 卡2 与卡4 口径打架

| 卡 | 说的是 | 口径 |
|---|---|---|
| 卡 2 | 绿 45 / 黄 112 / 红 3 | 按**餐**，一餐取最差灯 |
| 卡 4 | 钠 3 红 95 黄 · 脂肪 1 红 22 黄 · 糖 7 黄 | 按**营养素**逐项计 |

两处都在讲营养灯，却不标维度，这是"看不明白"的直接原因。**建议在卡4 标题或脚注加一句**：「按营养素逐项统计，与卡2 的按餐最差灯口径不同，数目不可直接相加」。

那片空白由新卡接住。**没有改动 `meals.json` 一个字节**。

### 8.1 后端（`api/routes/reports_route.py`）

| 新增 | 作用 |
|---|---|
| `_slot_of_hour(hour)` | 5–10 早 / 10–15 午 / 其余晚（0–5 点并入晚，不单开第四行） |
| `_bump_level(a, b)` | 同一格里多盏灯取最差 |
| `settle_meals(rows, start, end, today)` | 归并成顿 → 21 格；`/reports/weekly` 新字段 `meal_grid` |
| `_meal_over_list(grid)` | 只收红灯的顿；新字段 `over_list` |

口径：**相邻记录间隔 ≤60 分钟算同一顿**。实测本周 30 分钟切出 25 顿（超 21 格）、
120 分钟只剩 13 顿（把两顿并了）、60 分钟 = 17 顿 + 4 格空，与参考稿的 17/4 一致。

`records` 是**该格全部条数**（不去重），`dishes` 才去重；`level: null` 分两种——
`records === 0` 是"没记"，`records > 0` 是"记了没评估"，前端用虚线/点线两种框区分。

末尾那一列"今天"**完全无记录时裁掉**（`dropped_today` 记下日期），否则滚动窗口
跨 8 个日历日会把 7 列挤成 8 列、表头比格子还宽。
